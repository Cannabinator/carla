# CARLA V2V Research Platform - Agent Instructions

## Core Principle: Scientific Accuracy + Performance

**Always prioritize both scientific accuracy AND computational efficiency.** Never sacrifice one for the other - find solutions that optimize both.

---

## Scientific Accuracy Requirements

### 1. DSRC/V2X Channel Model
- **Cite real sources**: All channel model parameters must reference actual standards (ETSI EN 302 663, IEEE 802.11p) or peer-reviewed papers (Paier et al., Campolo et al., Sommer et al.)
- **Never hallucinate citations**: If unsure about a standard, say "requires verification" instead of inventing references
- **Validate physical models**: Test that PRR (Packet Reception Rate) behaves realistically across the operational range (10-150m for V2V)
- **Calibrate against measurements**: Default parameters should match empirical data from V2V measurement campaigns

### 2. CARLA Data Extraction
- **Always use snapshots for fresh data**: Use `snapshot.find(vehicle.id).get_velocity()` NOT `vehicle.get_velocity()` (which returns cached data from previous tick)
- **Vehicle-specific physics**: Use `vehicle.get_physics_control().wheels[0].max_steer_angle` for steering calculations, not generic approximations
- **Document fallback behavior**: When using fallbacks (e.g., cached data when snapshot unavailable), clearly label as "SCIENTIFICALLY INACCURATE - fallback only"

### 3. Simulation Parameters
- **Fixed timestep**: Maintain `fixed_delta_seconds = 0.05` (20 FPS) for reproducibility
- **Substepping constraint**: Ensure `fixed_delta_seconds <= max_substep_delta_time * max_substeps` (0.05 <= 0.01 × 10)
- **Seed reproducibility**: All random operations must use explicit seeds (default: 42 for simulation, 12345 for potholes if applicable)

## Performance Requirements

### 1. Thread Safety
- **Lock all actor mutations**: Use `PersistentCARLAServer._lock` for any vehicle/actor list modifications
- **Never mutate from wrong thread**: Actor lifecycle operations must happen in the tick thread or be properly synchronized
- **Minimize lock contention**: Keep critical sections as short as possible

### 2. Efficient Updates
- **V2V at 2 Hz**: Update V2V network every 10 frames (not every frame) - sufficient for BSM broadcast rate
- **Batch CARLA operations**: Use `apply_batch()` or `apply_batch_sync()` for spawning/despawning multiple actors
- **Spatial queries**: Use efficient distance calculations (squared distance when possible to avoid sqrt)

### 3. Memory Management
- **Avoid unbounded growth**: Ring buffers for stats (e.g., `_snr_ring` limited to 500 entries)
- **Cleanup on session end**: Spawn daemon threads for LiDAR cleanup, don't block tick loop
- **Lazy imports**: Import CARLA modules inside functions that need them (reduces startup time)

## Code Quality Standards

### 1. Configuration
- **All tunables in `src/config.py`**: Never use magic numbers in logic modules
- **Dataclasses for config**: Use `@dataclass` for `SimulationConfig`, `V2VConfig`, `DSRCConfig`, etc.
- **Document defaults**: Explain why each default value was chosen (standard requirement, measurement-based, etc.)

### 2. Type Safety
- **Type hints everywhere**: All function signatures must have complete type annotations
- **Optional for nullable**: Use `Optional[T]` when a value can be `None`
- **Pydantic for API**: Use Pydantic models for REST API request/response validation

### 3. Documentation
- **Docstrings with examples**: Include usage examples in docstrings for public APIs
- **Standards references**: Link to SAE J2735, ETSI standards, or research papers in module docstrings
- **Comment complex physics**: Explain the physical meaning of equations in channel models

## Testing Requirements

### 1. Scientific Validation
- **Test channel model behavior**: Verify PRR stays realistic (e.g., >0.9 for N≤15 vehicles at 2 Hz)
- **Test at operational ranges**: Validate RF model varies meaningfully within 10-150m
- **Compare against baselines**: Document expected vs actual behavior in test output

### 2. Performance Validation
- **Measure update rates**: Ensure V2V network updates at 2 Hz (not faster, not slower)
- **Check thread safety**: Verify no race conditions in actor lifecycle
- **Profile if slow**: Use Python profiling tools before optimizing

### 3. Integration Testing
- **Test with Docker**: Validate changes work in containerized environment
- **Test without CARLA**: Unit tests should not require running CARLA server
- **End-to-end scenarios**: Maintain working demo scenarios as integration tests

## Agent Behavior Guidelines

### When Making Changes:
1. **Check scientific accuracy first**: Does this match the physics/standards?
2. **Consider performance impact**: Will this slow down the tick loop?
3. **Update tests**: Add/modify tests to validate the change
4. **Update documentation**: Reflect changes in `docs/agents/audit.md`
5. **Run validation**: Execute `test_scientific_fixes.py` before committing

### When Reviewing Code:
1. **Verify citations**: Are standards/papers correctly referenced?
2. **Check thread safety**: Are actor mutations properly locked?
3. **Validate config**: Are tunables in `src/config.py`?
4. **Test coverage**: Are there tests for the new behavior?

### When Debugging:
1. **Check snapshot usage**: Is velocity/transform from snapshot or cached?
2. **Verify timing**: Are updates happening at the correct frequency?
3. **Profile before optimizing**: Use `pylancePythonProfiling` to find bottlenecks
4. **Check CARLA docs**: Use official CARLA documentation for API behavior

## Quick Reference

### Critical Files:
- `src/v2v/dsrc_channel.py` - DSRC channel model (CSMA/CA, path loss, PRR)
- `src/v2v/messages.py` - BSM/DENM/CAM message creation (use snapshots!)
- `src/config.py` - All configuration constants
- `src/server/persistent_world.py` - Main simulation loop
- `src/utils/potholes.py` - Pothole management (manual registration only)

### Key Standards:
- **SAE J2735**: BSM, DENM, CAM, MAP, SPAT messages
- **ETSI EN 302 663**: DSRC TX power (23 dBm), sensitivity (-85 dBm)
- **IEEE 802.11p**: CSMA/CA channel access
- **ETSI TS 103 300-3**: VRU awareness messages

### Performance Targets:
- **V2V update rate**: 2 Hz (every 10 frames at 20 FPS)
- **CSMA/CA PRR**: >90% for N≤20 vehicles, >60% for N≤100
- **RF model variation**: Meaningful PRR change within 10-150m range
- **Tick loop**: Maintain 20 FPS (0.05s per frame)
